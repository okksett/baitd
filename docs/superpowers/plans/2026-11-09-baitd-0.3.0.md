# Baitd 0.3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship 0.3.0 with:
- the AI model chosen in Ajustes from a live list;
- automatic retries, and a Reintentar button that resumes failed work;
- a clearer Clipping form;
- download quality you can choose;
- a busy-port check that actually works;
- a Windows installer, and updates in one click.

**Architecture:**
- **App:** a local Flask + waitress app (`src/baitd`) with a vanilla JS UI (`web/static/app.js`, `web/templates/index.html`, i18n JSON files).
- **Data:** settings live in `settings.json` (`config.SETTINGS_DEFAULTS`), profiles in `profiles.json`, and the job queue in `queue.json`.
- **Windows packaging:** a PyInstaller one-folder build (`packaging/baitd.spec`), built in `.github/workflows/build.yml`. Inno Setup wraps the resulting `dist/Baitd` folder into the installer.

**Tech Stack:** Python 3.10+, Flask, waitress, requests, yt-dlp, faster-whisper, pytest, PyInstaller, Inno Setup 6, GitHub Actions.

**Spec:** `docs/pendientes.md`, items 0, 0b, 0c, 0d, 1-4, 6 and 7, plus the user's rulings of 2026-11-09 below. The YouTube-session work (item 5) is already on this branch as commit `c572003`.

## Review Focus

1. **Old profiles keep their model.** A profile with `llm_model` already set (for example `gemini-3.6-flash`, typed by hand last week) must keep working after the upgrade. A one-time migration copies the value into Ajustes, and a test pins it (Task 2).
2. **Retry resumes, and removal cleans up.**
   - Retrying a failed clip job must not download or transcribe the video again.

5. **Ajustes before any key is saved.** The model dropdown still shows "Por defecto" and "Otro…" with a hint, not an error box (Task 2).

- Test: `tests/test_jobqueue.py` (or whichever queue test file is in use), `tests/test_clip_pipeline.py`, `tests/test_server_clip.py`

**Interfaces:**
- **`JobQueue.retry(id: str) -> None`:**
  - Works only for status `error` or `cancelled`.
  - Resets `status="pending"`, `error=""`, `step=""`, `step_index=0`, `percent=0` and `output=""`.
  - Keeps `payload`, `profile` and `script`.
  - Any other status raises `ValueError`, which the route turns into 409.
- **Route `POST /api/jobs/<id>/retry`:** returns 200 `{}`. An unknown id returns 404, and a job that cannot be retried returns 409.
- **Clip resume contract:**
  - **Reuse the download.** Right after `run_clip_auto` or `run_clip_analyze` fetches a URL source, rewrite the item's payload source to `{"source_id": src.id, "fetched": true}`. Persist it through the queue's save path, so a retry reuses the file.
  - **Clean up on removal.** `jobqueue._release` and `pipeline` treat `fetched: true` sources the way they treat downloaded sources today: deleted when the item is removed or cleared, unless `keep_sources` is on or another job uses them.
  - **Keep the source on failure.** `_discard` no longer deletes a source that the payload now references. It still removes the output folder.
  - **Save the transcript.**
    - After transcribing, `_understand` writes `fuentes/<id>/transcript.json` containing `{"key": [transcriber, model, language_or_null], "transcript": <Transcript dict, same format as in analyses>}`.
    - Before transcribing, if that file exists with the same key, `_understand` loads it and skips step 2 (`steps.end(2)`).
- **UI:** a `data-job-act="retry"` button labeled "Reintentar", visible for every job kind when the status is `error` or `cancelled`.

**Interfaces:**
- **Constants:**
  - `updater.REPO = "okksett/baitd"`
  - `updater.LATEST_API = "https://api.github.com/repos/okksett/baitd/releases/latest"`
  - `updater.DOWNLOAD_PREFIX = "https://github.com/okksett/baitd/releases/download/"`
- **`updater.parse_version(s: str) -> tuple[int, ...]`:** strips a leading `v`. Non-numeric input returns `()`.
- **`updater.check(current: str, get=requests.get) -> dict | None`:**
  - Sends a GET with `timeout=5` and the headers `Accept: application/vnd.github+json` and `User-Agent: Baitd/<current>`.
  - Returns `{"version", "page", "setup_url", "sums_url"}` when the release tag is newer than `current`, otherwise None.
  - Any network or parse error returns None.
  - An asset URL that does not start with `DOWNLOAD_PREFIX` is dropped (set to "").
- **`updater.state`:** a module-level dict `{"latest": dict | None}`. `start_background_check(current)` fills it from a daemon thread that runs once.
- **`updater.can_install(latest) -> bool`:** `sys.platform == "win32" and getattr(sys, "frozen", False) and latest.setup_url and latest.sums_url`.
- **`updater.download_and_verify(latest, dest_dir: Path, get=requests.get) -> Path`:**
  1. Fetch `SHA256SUMS` and parse the line for `Baitd-Setup.exe`. Reuse the approach of `ytdlp_loader._expected_hash`, generalized to take the asset name.
  2. Stream the installer into `dest_dir/"Baitd-Setup-<ver>.exe.part"`, hashing as it downloads.
  3. If the hash does not match, or the line is missing, delete the file and raise `UserError("No se pudo verificar la actualización", "Descárgala desde la página de Baitd")`.
  4. On success, `os.replace` the file to `.exe` and return its path.
- **`updater.launch_installer(path: Path) -> None`:** `subprocess.Popen([str(path), "/SILENT", "/SUPPRESSMSGBOXES", "/NORESTART", "/UPDATE=1"], close_fds=True, creationflags=DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP)`.
- **Routes:**
  - `GET /api/update` returns `{"current", "latest": dict|null, "can_install": bool}`.
  - `POST /api/update/install`:
    - returns 409 when the update cannot be installed;
    - otherwise downloads and verifies into `data_dir()/actualizaciones`, launches the installer, calls `request_shutdown()` and returns `{"ok": true}`.
- **UI:**
  - When `latest` is set, `#update-bar` shows "Hay una versión nueva: {v}" with these buttons:
    - **"Actualizar"**, when `can_install`:
      - it first asks for confirmation with the key `settings.update_confirm`: "Se cerrará Baitd, se instalará la versión {v} y se volverá a abrir. Un video en curso volverá a la cola.";
      - after the POST it shows a page in the style of `quit-done`: "Instalando la actualización… Baitd se abrirá solo."
    - **"Descargar"**, when it cannot install: opens `latest.page`.
    - **"✕"**: hides the bar for that version. The choice is stored in localStorage, inside try/catch.
  - Ajustes gets the checkbox "Buscar actualizaciones al abrir" (`check_updates`).
